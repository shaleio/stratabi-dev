DESIGN GUIDE — make dashboards look finished, not generated (follow unless the user asks otherwise)

Cards and color
- Every tile gets an OUTLINED card: "card": {"color": "<c>", "outline": true}.
- Colors tell a story; tiles that belong together share a color:
    secondary = controls and context (inputs, filters, selectors, reference lists)
    primary   = the headline numbers and main results
    info      = supporting charts, trends and actions
    warning / danger = ONLY exceptions, alerts, SLA breaches or operationally critical data
- Never use more than 3-4 colors on a page. Don't color a tile warning/danger for decoration.
- An intro/heading markdown tile has no card chrome: "card": {"show_header": false}, no color.

Layout
- Bootstrap 12-column grid. Size to content: a KPI or single input 3, a small chart 4-6,
  a main chart 6-9, tables and wide charts 12. A row's widths add up to 12.
- Many controls? Stack them in a left column: same row, "position": {"stack": "controls", "width": 3},
  main content to the right (width 9, or 6 + a 3-wide KPI stack). Use this by default when there
  are 3+ inputs and the user didn't ask for another layout.
- Start with a one-line intro markdown tile (## Title + one sentence). Don't repeat the tile title
  inside its markdown.
- Give charts and tables an explicit height string ("320px", "40vh") so rows line up.

Tiles
- Input tiles always have a "title" (it becomes the card header) and a sensible default "value".
- Tiles fed by an input list it in "triggered_by" (the input tile id) and use "load": {"mode": "input"}.
- Charts: "theme_colors": true instead of hard-coded colors; trim margins ("margin": {"t": 10}).
- Prefer native blocks over HTML: markdown for KPIs and notes, table for rows, plotly for charts.
  Native results are stored as data (CSV/Parquet/Markdown) that can be queried and mined later;
  HTML is opaque. Use raw_html only when the view is genuinely novel. When you do, keep its
  background transparent and inherit the text color so it blends with the card (in apps, the
  module's ui.card_style "match" does this).
- Lists and views that re-read data: "controls": {"run_button": true, "run_icon": "refresh"};
  actions keep the default ▷. Action (manual) tiles get a "placeholder" explaining what ▷ does.
- Async tiles that refresh in place: "load": {"keep_previous": true}.
- Tables that people will export: "artifact": {"download": true}.

Common mistakes that fail validation or look broken
- "card" is an object, never a string. Heights are strings with units, never numbers.
- Don't invent fields; the schema is closed. Every tile id is unique.
- Don't put a whole page in one raw_html tile. Don't leave a row half empty.
